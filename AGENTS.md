# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- `CONTRACT.md` and everything under `contract/` are the ratified answer key: never edit them. `createForeman` (issue #7) now wires `src/record` + `src/line` + `src/brain` + `src/config` together in `src/foreman/`, so most contract rules are green. Rule 4 (delivery validation, issue #9), rule 6 (verdict, issue #10), and rule 10's cap-refusal test (issue #11) are still legitimately red pending those issues — `npm test` failing on exactly those is expected, not a bug; any other red contract test is a real regression.
- `npm test` first runs `tsc --noEmit`, then runs every `*.test.ts` under `contract/` (the answer key, do not touch) and `src/`, at any depth - discovery is a `find`, not a shell glob, so a nested test file is never silently skipped. When adding a feature, colocate its test next to the source file it covers (`foo.ts` + `foo.test.ts`), matching how `contract/` colocates one test file per rule.
- Module layout under `src/<feature>/`: `errors.ts` (a typed error class with a `code` for branching, message written to be shown to the Client verbatim), one file per behavior (e.g. `load.ts`, `registry.ts`), an `index.ts` barrel, and a `helpers/` subfolder for test-only fixtures. A `types.ts` holds internal shapes only where a module has any; a type that also appears in `contract/surface.ts` (the seam the module is implementing) is declared there once and imported into `src/` with `import type` (issue #45) — never redeclared. See `src/config/` as the reference example for a module with real internal types, and `src/brain/types.ts` / `src/foreman/` for modules that now hold no internal types of their own, only re-exports or `import type` from the contract.
- The record home (`~/.fabrica` by default) is never hardcoded past the outermost CLI layer — every function that touches it takes `recordHome: string` as an explicit parameter, so parallel workers/tests never share state. Tests use throwaway temp dirs (`mkdtempSync`), never the real home.
- Use LANGUAGE.md's vocabulary (Client, Factory, ProductionLine, Foreman, Worker, task, checks, delivery, verdict, caps) in code and messages — don't invent synonyms. `Fabrica` is the Factory's name (`~/.fabrica`, the `fabrica` command, and the factory's own types `FabricaTask`/`FabricaEvent`/`FabricaEventName`) — it is not a second name for the Foreman. `Foreman` is settled (PR #43) as the name for `src/foreman/`'s delegator module, its interface (`contract/surface.ts`'s `Foreman`), and `createForeman`; do not rename these to "Fabrica" again.
- `contract/surface.ts` is purely declarative (issue #45): every shared type (`Brain`, `Delivery`, `Foreman`, etc.) is declared there exactly once and imported into `src/` as a type (`import type`, erased at compile time — no runtime dependency). It has no functions except the still-unbuilt `validateDelivery` stub (issue #9) and imports nothing from `src/`. `src/index.ts` is the single public entry point implementing those seams — `createForeman`, `ForemanError`, etc. — and is what `contract/*.test.ts` and any future CLI import from, never an internal module path directly.
- `src/line/helpers/fixture.ts` and three `src/foreman/*.test.ts` files import `makeFixtureRepo`/`fingerprint` from `contract/helpers/` on purpose (issue #45 decision, kept deliberately): both suites measuring the "untouched checkout" proof with the same `fingerprint()` ruler is a feature, and these are test-only imports, not production code depending on the contract. Don't "fix" this by duplicating the fixture into `src/`.
- `src/record/` (issue #3) is the append-only event log (`events.jsonl`) plus per-task folders; its structural append-only proof spawns real `tsx` child processes (see `src/record/helpers/concurrent-append-worker.ts`) rather than interleaving async calls in one process, since only genuine OS-level concurrency can prove a write can't be torn. Reuse that pattern for any other append-only file (e.g. `transcript.log`).
- On macOS, `os.tmpdir()` resolves through a `/var` -> `/private/var` symlink. Any code or test that computes a path under a temp dir and later compares it against a `realpathSync`'d value (as `src/line` does for its worktree paths) must compare against the realpath'd form on both sides, or the comparison spuriously fails.
- `src/line/` (ProductionLine: creating/destroying the throwaway git worktree per task) is the reference example for path-safety code: never delete or write to a path without first proving via `git worktree list` that it's the exact throwaway path expected, not a live checkout. `destroyProductionLine` returns a `TeardownResult` (`{ status: "destroyed" | "already-destroyed" }`), not `void` — a second teardown of the same line is idempotent success, not a thrown `unsafe-teardown`; only a workdir that never was this line's still throws.
- `src/brain/` is the socket for rule 8 ("No favorite brain"): `types.ts` re-exports the `Brain` interface (and `BrainWorkOptions`, `BrainWorkResult`, `TranscriptEntry`) as types from `contract/surface.ts` — nothing declared locally any more (issue #45) — and `helpers/fake-brain.ts` is the src-side fake. `src/brain/adapters/` is the only directory anywhere under `src/` allowed to name a brain, model, or vendor - `contract/rule8.no-favorite-brain.test.ts` scans the rest of `src/` for those names and skips that directory by name. This scan also flags a literal `CLAUDE.md`/`AGENTS.md` mention (the word "claude") anywhere under `src/` outside `adapters/` — write around it (e.g. "the project's root agent-memory file") in any `src/` prose, not just code.
- `src/brain/adapters/claude-code.ts` is the reference CLI adapter (one that wraps a coding-agent command, vs. a direct API adapter - see `adapters/README.md`). Read `claude-code.md` before writing another CLI adapter: real, verified-on-the-machine behavior there generalizes, e.g. non-interactive mode has no TTY to approve tool permissions (a throwaway worktree needs an explicit permission-mode bypass or every write is silently denied), and a resumable session is scoped to the `cwd` it was created in.
- `src/foreman/` (issue #7) is `createForeman`'s real implementation: registers a task, cuts a ProductionLine, runs the counted attempt loop, verifies with the project's check, delivers, tears down. `Delivery` and `Receipt[]` are stored on the `"delivered"` event's `details` (there's no dedicated record file for them) — `deliveryOf`/`receiptsOf` read that back, never parse `delivery.md`. See `src/foreman/README.md` for why `attempts` behaves differently when given explicitly vs. omitted, and why the check command defaults to a `check.sh` convention.
